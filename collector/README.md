# 이노스마트 진단 수집기 (ismart-collector)

Windows 환경에서 **제3 보안SW(itShield 등 후킹/주입 에이전트)와의 호환성 충돌**을 현장에서 안전하게 진단·수집하기 위한 포터블 도구. 수집 결과는 공통 이슈 번호로 TrustLink에 전달된다.

> 상태: **1차 포터블 스캐폴드**(컴파일·동작 확인). 네이티브 수집·업로드·서명·자가업데이트는 결정 후 단계적으로 채운다.

---

## 1. 실행 모델 — 단일 바이너리 2모드

조사 결과(Velociraptor 패턴)를 따른다. 포터블의 가벼움과 에이전트의 자가업데이트를 **한 바이너리**로 얻는다.

| 모드 | 호출 | 동작 | 설치 |
|---|---|---|---|
| 포터블(기본) | 더블클릭/무인자 | 1회 수집 → 번들 → (업로드) → 종료 | 없음 (**1차**) |
| 상주(선택) | `--install` | per-user 예약작업 등록 → 주기 업데이트·룰 갱신·반복 | 가벼움 (**2차**) |

- 설정·토큰은 **바이너리에 넣지 않고** 옆의 `ismart-collector.conf`(사이드카)에서 읽는다 → **코드 서명 유지**(Velociraptor 교훈).
- 상주는 Windows 서비스가 아니라 **per-user 예약작업** → 관리자 권한·레지스트리 변경 불필요.

## 2. 아키텍처(4계층)

1. **코어(Rust exe)** — 오케스트레이션·수집·마스킹·업로드·서명검증·자가업데이트. 권한 필요한 일은 코어만.
2. **룰 팩(서명·선언형 TOML)** — "무엇을 어떻게 수집·판정" 레시피. 데이터라 안전. 새 충돌원은 룰만 배포.
3. **도구 어댑터(허용목록)** — 네이티브 Win32 수집 또는 외부 도구 래핑.
4. **WASM 플러그인(샌드박스, 2차)** — 복잡 로직. 능력 제한 호스트 API만.

확장은 선언형 룰 → WASM 순. 미서명/임의 네이티브 코드 실행은 하지 않는다.

## 3. 수집 항목(읽기 전용)

| 항목 | 내용 |
|---|---|
| `os_info` | Windows 에디션·빌드·패치 수준 |
| `security_software` | 설치 보안SW + 로드/주입 모듈에서 **후킹 에이전트 탐지**(itShield 등) |
| `process_modules` | 프로세스별 로드/주입 DLL·서명 여부 |
| `product_logs` | 이노스마트플랫폼 로그·버전·설정 경로 |
| `crash_dumps` | WER/크래시 덤프 경로·발췌 |

- 모든 항목은 **수집 즉시 마스킹**(사용자 경로·토큰·비밀 가림). 시스템 변경 없음.
- 수집 전 **고지·동의**, 수집 항목 미리보기.

## 4. 수집 범위 — 설정 가능 (제품 한정 ↔ 시스템 전역)

**둘 다 설정으로 전환**한다. 기본은 제품 한정(최소 수집).

**설정 우선순위**: `명령행 플래그` > `사이드카 conf` > `기본값(product)`
- 관리자가 TrustLink에서 이슈 발급 시 `ismart-collector.conf`에 값을 심어 전달 → 사용자는 신경 쓰지 않음.
- 현장에서 급히 바꿀 땐 `--scope system` 플래그로 덮어씀.

```ini
# ismart-collector.conf (실행파일 옆, 토큰은 바이너리 밖)
issue_id = TL-2026-0042
scope    = product            # product(기본) | system
profile  = ismart-platform    # 제품 프로파일(여러 제품 지원)
collect  = os_info,security_software,process_modules,product_logs,crash_dumps  # 생략=전체
```

| scope | 의미 | 민감도 |
|---|---|---|
| `product`(기본) | **제품 프로파일**에 매칭되는 경로·프로세스·로그만. 이노스마트플랫폼에 개입하는 후킹 에이전트만 | 낮음(최소 수집) |
| `system` | 설치 보안SW 전체·전체 프로세스 트리 등 전역 | 높음 → **추가 동의** |

- **제품 프로파일**(서명 룰 팩 `profiles/ismart-platform.toml`): "이노스마트플랫폼"이 무엇인지(설치 경로·프로세스명·로그 glob)를 정의. 제품이 바뀌어도 프로파일만 갱신. `profile=` 로 여러 제품 지원.
- **카테고리 토글**: `collect=` 로 항목 개별 on/off(예: 덤프 제외).
- 설계 근거: 기본 최소 수집(개인정보 노출 최소) + 필요 시 관리자 판단으로 전역 확장.

## 5. 지원 OS

- **지원**: Windows 10 (1809+) · Windows 11 · Windows Server 2016/2019/2022/2025, **x64**.
- 미지원: Windows 7/8.1(EOL). ARM64는 2차 검토.
- 이 도구는 **Windows 전용**. 비-Windows 호스트에서는 구조 검증용 스텁으로만 컴파일된다.

## 6. 성능 목표(예상)

Rust·크기 최적화 단일 바이너리 기준. (실측은 네이티브 구현 후 갱신)

| 지표 | 목표/예상 |
|---|---|
| 바이너리 크기 | **2–6 MB**(단일 exe, 런타임 무의존). Sysinternals 번들 시 +수 MB |
| 메모리(수집 중) | 대체로 **30–80 MB**. ETW 추적 시 일시 증가 |
| CPU | 평시 유휴. 수집 피크 수 초, ProcMon류 추적 구간만 일시 상승 |
| 수집 시간 | 기본 프로파일 **수십 초~2분**(덤프 포함 시 증가) |
| 디스크(번들) | 보통 **수 MB~수십 MB**(덤프 포함 시 수백 MB) |

## 7. 빌드 · 배포 · 버전 관리 · 서명

### 빌드
```sh
cargo build --release            # 로컬(호스트) 구조 검증
# Windows 배포 바이너리는 Windows 러너에서:
cargo build --release --target x86_64-pc-windows-msvc
```
> 현재 개발 호스트(macOS)에는 Windows 타겟/링커가 없어 로컬에서 .exe 생성 불가 → **CI(windows-latest)**에서 빌드.

### 배포 · 버전 관리(제안)
- **GitHub Releases**에 버전별 서명 아티팩트 게시: `ismart-collector-vX.Y.Z-x64.exe` + `.sha256`.
- **구버전 보존**(릴리스 히스토리) → TrustLink 문서의 **다운로드 페이지**에서 최신+구버전 링크 제공.
- 자가업데이트(2차)는 **TUF**(`tough`)로 freshness·롤백 방지 + 임계 서명.

### 코드 서명 · 키 관리
- 배포 .exe는 **Authenticode 코드서명**(EV 인증서 권장 — SmartScreen·보안SW 오탐 감소).
- 룰·업데이트 매니페스트는 **TrustLink 전용 서명키**로 서명, 코어에 공개키 내장·검증.
- 키 관리: **root 키는 오프라인·다중 서명**, 서명키는 HSM/보안 보관, **정기 롤테이션**. (TUF 역할: root/targets/snapshot/timestamp)

## 8. 보안 불변식(타협 금지)

- 모든 룰·플러그인·업데이트는 **서명 검증 후** 실행
- 확장은 **선언형 + WASM 샌드박스**로만, 임의 코드 실행 금지
- 어댑터 허용목록·읽기 전용·리소스 상한
- 업로드 대상은 **TrustLink 한 곳**, 외부엔 번호·링크만(카카오 등에 번들 금지)

## 9. 현재 소스 구조

```
collector/
  Cargo.toml
  src/
    main.rs      # CLI·모드 분기(포터블/--install/--version)
    config.rs    # 사이드카 설정(토큰은 바이너리 밖)
    collect.rs   # 수집기 트레이트 + 플랫폼(windows 네이티브/스텁)
    redact.rs    # 마스킹
    bundle.rs    # 번들·매니페스트
```
